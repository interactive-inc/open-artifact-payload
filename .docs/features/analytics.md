# ダッシュボードのアクセス解析

## 概要

管理画面のダッシュボードに、GA4 の集計と問い合わせ件数を表示します。タスクカードの下、最近の更新の上に出ます。毎日開いたときに、アクセスの増減やよく読まれたページを GA4 の画面へ移らずに確かめるための機能です。

表示する内容は次のとおりです。

- ユーザー数・表示回数・セッション数・問い合わせ件数と、直前の同じ長さの期間からの増減
- 日ごとのユーザー数の推移（実線が今の期間、点線が前の期間）
- 表示回数の多いページの上位 10 件（パスはクエリ文字列を含まない）
- 流入元（自然検索・直接・SNS などの GA4 標準の分類）ごとのセッション数

期間は 7 日・28 日・90 日から選べ、初期値は 28 日です。終わりは日本時間の昨日で、今日の分は含めません。問い合わせ件数は CMS に保存された問い合わせを数えるため、GA4 を接続していなくても表示されます。

レポートの文章化や改善提案は CMS では行いません。必要な場合は、手元の AI クライアントから GA4 や CMS の MCP を使ってください。設計の判断は [[decisions/008-ga4-analytics-dashboard|管理画面のダッシュボードでGA4のアクセス解析を見せる]] にあります。

## 有効にする

`src/cms/project-features.ts` の `enableAnalytics` を `true` にします。`false` の案件では、設定画面とダッシュボードのパネルが登録されません。

テンプレートを取り込んだら、設定画面のテーブルを作るマイグレーションを適用します。ローカルは `vp run payload migrate`、デプロイ先は `make deploy-db` です。

## 導入の手順

サービスアカウントはサイトごとに 1 つ作ります。複数のサイトで共有すると、ある案件の管理者がプロパティ ID を書き換えるだけで他の案件の数字を読めてしまうためです。

- Google Cloud のプロジェクトで「IAM と管理 > サービスアカウント」を開き、サイト名が分かる名前でサービスアカウントを作る。プロジェクトへのロールは付けない
- 作ったサービスアカウントの「鍵」から JSON の鍵を作成してダウンロードする
- Google Cloud コンソールの「API とサービス」で「Google Analytics Data API」を有効にする
- GA4 の「管理 > プロパティのアクセス管理」で、サービスアカウントのメールアドレスを「閲覧者」として追加する
- 鍵をデプロイ先に登録する: `wrangler secret put GA4_SERVICE_ACCOUNT_JSON --env=production < key.json`
- 管理画面の「システム > アクセス解析設定」で、GA4 プロパティ ID を入力する。GA4 の「管理 > プロパティの詳細」にある数字だけの ID で、G- から始まる測定 ID ではない。入力できるのはサービス管理者だけ
- ダッシュボードを開き、数字が出ることを確かめる

ダウンロードした鍵のファイルは、登録が済んだら手元から削除します。

組織のポリシーでサービスアカウント鍵の作成が禁止されている場合、この方式は使えません。Google Cloud の組織ポリシー `iam.disableServiceAccountKeyCreation` を確認してください。

## GA4 がクライアントのアカウントにある場合

サービスアカウントの追加はクライアントの GA4 管理者に依頼します。プロパティ ID も合わせて教えてもらいます。依頼文の例です。

```text
管理画面にアクセス解析を表示するため、GA4 の閲覧権限の追加をお願いします。

対象: （サイト名）の GA4 プロパティ
操作: GA4 の「管理 > プロパティのアクセス管理」で、次のメールアドレスを「閲覧者」として追加
メールアドレス: （サービスアカウントのメールアドレス）

あわせて、「管理 > プロパティの詳細」に表示される数字だけのプロパティ ID を教えてください。
閲覧者の権限では、GA4 の設定の変更やデータの削除はできません。
不要になった場合は、同じ画面からいつでも外していただけます。
```

クライアントの組織が外部のアカウントを追加できないように制限している場合は、追加できないことがあります。その場合は、クライアントの Google Cloud でサービスアカウントを作って鍵を渡してもらう形でも動きます。

## 見られるロール

「アクセス解析設定」の「アクセス解析を見られるロール」で、管理者と編集者から選びます。初期値は管理者だけです。サービス管理者は選択に関係なく常に見られます。何も選ばなければサービス管理者だけが見られます。この項目は管理者以上が変更できます。

編集者を含めた場合も、編集者に見えるのは問い合わせの件数だけで、問い合わせの内容は見えません。

## 取得のしくみ

ダッシュボードを開いたときに GA4 Data API へ問い合わせ、結果を 3 時間保存して使い回します。保存先は Payload の KV（`payload_kv` テーブル）です。日本時間の日付が変わったときは、3 時間以内でも取り直します。

GA4 への問い合わせは 4 種類の集計を 1 回にまとめ、10 秒で打ち切ります。待っている間もダッシュボードの他の部分は先に表示されます。期間ごとに 1 日 8 回程度の呼び出しで、GA4 の無料枠に対して十分に小さい量です。

GA4 は集計に最大 48 時間ほどかかります。昨日の数字は、後から少し増えることがあります。

## 止める・移管する

- GA4 の「プロパティのアクセス管理」でサービスアカウントを外すと、管理画面の状態に関係なく取得できなくなる。GA4 がクライアントのアカウントにある場合は、クライアント側の操作だけで止められる
- Google Cloud でサービスアカウントの鍵を削除しても止まる
- 移管先が自前の GA4 を使う場合は、移管先でサービスアカウントを作り、鍵とプロパティ ID を設定し直す
- 機能ごと外す場合は `enableAnalytics` を `false` にする

## うまく表示されないとき

パネルと「アクセス解析設定」の接続状態に、原因に応じた文が出ます。

- 「GA4 が未接続です」: 鍵（`GA4_SERVICE_ACCOUNT_JSON`）かプロパティ ID が設定されていない
- 「鍵を読み取れないか、Google に拒否されました」: 鍵の JSON が壊れている、または鍵が削除・無効化されている。ダウンロードした JSON をそのまま登録し直す
- 「GA4 を閲覧する権限がありません」: サービスアカウントが GA4 プロパティに追加されていない、または Google Analytics Data API が有効になっていない
- 「GA4 が問い合わせを受け付けませんでした」: プロパティ ID が違う
- 「呼び出し上限に達しました」「GA4 から応答がありません」: 時間をおいて開き直す

取得に失敗しても前回の結果があれば、それに「最新の取得に失敗しました」と添えて表示します。

## ローカル開発

`.env` に鍵を 1 行で設定します。ダウンロードした JSON は複数行のため、`jq -c . key.json` で 1 行にしてから貼り付けます。

```bash
GA4_SERVICE_ACCOUNT_JSON='{"type":"service_account","client_email":"...","private_key":"-----BEGIN PRIVATE KEY-----\n...","private_key_id":"..."}'
```

ローカルの D1 でもアクセス解析設定にプロパティ ID を入力すると、本物の GA4 の数字を表示できます。
